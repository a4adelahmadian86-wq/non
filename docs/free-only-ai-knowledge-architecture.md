# معماری مقاوم و رایگان پایگاه دانش FARAST

**مبنای ممیزی:** کد شاخهٔ `main` پس از commit `58b8b114a5a6f41ddf58bded91cb3e5476f0712d` و مخزن مکمل `a4adelahmadian86-wq/Voice-typing`.

**هدف:** هزینهٔ صفر تا حد ممکن، حفظ داده در ایران برای زمان قطعی بین‌الملل، استفاده از مدل‌های قوی از طریق API، داشتن مسیر جایگزین، و مهم‌تر از همه حفظ ساختار فعلی بدون ساخت پایگاه داده یا صف موازی.

## 1. نتیجهٔ ممیزی سایت فعلی

بخش مهمی از زیرساخت از قبل وجود دارد و باید حفظ شود:

- منبع حقیقت کاربران، محصولات، مجوزها، صف و دانش ساختاریافته، دیتابیس فعلی Laravel/MySQL است.
- متن استخراج‌شده، صفحه‌ها، chunkها و factهای اسناد محصول در جدول‌های موجود `store_product_document_*` نگهداری می‌شوند.
- حافظهٔ کاربر در جدول جداگانهٔ `farast_user_knowledge` قرار دارد؛ دانش تأییدشدهٔ عمومی و حافظهٔ خصوصی کاربر نباید در یک مجموعه ادغام شوند.
- فایل‌های حساس محصول و مشتقات پردازش‌شده از `StorageManager` با طبقه‌بندی `critical` به `iran_primary` می‌روند. فایل‌های غیرحساس در `foreign_primary` قرار می‌گیرند.
- انتقال فایل، بررسی سلامت، checksum، بازیابی انتقال نیمه‌تمام و بکاپ رمزگذاری‌شدهٔ AES-256 در کد موجود است. `iran_backup` نیز به‌عنوان مقصد دوم پیش‌بینی شده و با `FARAST_ENABLE_IRAN_BACKUP=true` فعال می‌شود.
- صف فعلی Laravel پایدار و مبتنی بر دیتابیس است؛ برای این طرح صف جدیدی ساخته نمی‌شود.
- `ProductSupervisorClient` از قبل endpoint اصلی و fallback را می‌پذیرد. این تغییر، fallback را برای پاسخ‌های موقت و محدودیت ظرفیت `408/425/429/5xx` نیز فعال می‌کند؛ خطاهای احراز هویت و اعتبارسنجی پنهان نمی‌شوند.

### ایرادهای واقعی که باید قبل از اتصال Production رفع شوند

1. `FARAST_AI_GATEWAY_URL` در نمونهٔ تنظیمات به سرویس Render مربوط به گفتار اشاره می‌کند؛ کد مخزن مکمل آن سرویس فقط مسیرهای ASR/TTS دارد و endpoint چت `/v1/chat/completions` را در آن پیاده‌سازی نکرده است.
2. `GeminiEditorProvider` در صورت شکست درگاه، مستقیماً به Gemini وصل می‌شود. همچنین مستند استقرار، نشانی مستقیم Cloudflare API را به‌عنوان fallback معرفی کرده است. این رفتار با شرط «سایت مستقیماً به ارائه‌دهنده وصل نشود» سازگار نیست.
3. مخزن مکمل `Voice-typing` از قبل `runflare-gateway` و اسکریپت استقرار Runflare دارد؛ بنابراین در مخزن `non` درگاه دومی نمی‌سازیم. در PR #16 این درگاه به‌صورت bridge بدون state به Worker اصلی وصل می‌شود، Qwen محلی و fallbackهای Gemini/Groq به‌صورت پیش‌فرض غیرفعال می‌شوند و اسکریپت استقرار فقط gateway را deploy می‌کند. کد Qwen حذف نشده و در پوشهٔ legacy باقی می‌ماند؛ سرویس Production انتخاب‌شده نیست.
4. `services/product-supervisor/README.md`، Back4App را نامزد استقرار معرفی می‌کند، در حالی که `render.yaml` نیز یک استقرار Render تعریف کرده است. بررسی تازهٔ صفحهٔ رسمی Back4App نشان می‌دهد URL پلن رایگان Container موقت است و پس از ۶۰ دقیقه منقضی می‌شود؛ پس برای endpoint دائمی Production انتخاب نمی‌شود. Render رایگان نیز بعد از idle می‌خوابد و برای پاسخ سریع و همیشه‌فعال تضمین ندارد. در `.env.example` نشانی واقعی Product Supervisor خالی است؛ هیچ‌یک را سرویس Production فعال فرض نمی‌کنیم و چند runtime را بدون نیاز هم‌زمان راه‌اندازی نمی‌کنیم.

## 2. محدودیت اول: فیلترشدن یا محدودیت منطقه‌ای ارائه‌دهنده

VPN رایگان عمومی یا پراکسی ناشناس را وارد زیرساخت Production نمی‌کنیم. چنین واسطه‌ای ممکن است خودش مسدود شود، IP ناپایدار داشته باشد، محتوای درخواست‌ها را ببیند یا شرایط استفادهٔ ارائه‌دهنده را نقض کند. اگر ارائه‌دهنده استفاده از یک منطقه را ممنوع کرده باشد، عبور از محدودیت جغرافیایی راهکار قابل‌قبول یا تضمین‌شده نیست.

راه درست، **درگاه API با چند endpoint مستقل** است:

- یک Cloudflare Worker واحد برای چت، ویرایشگر و Product Supervisor ساخته شده است؛ Laravel فقط URL همین درگاه را می‌بیند. GPT-OSS 20B برای متن عمومی، GPT-OSS 120B برای بازبینی metadata، Moondream برای تصویر و Whisper برای صوت pin شده‌اند. سیاست رسمی Workers AI برای inference استاندارد Zero Data Retention و عدم استفاده برای آموزش را اعلام می‌کند. سهمیهٔ رایگان ۱۰٬۰۰۰ Neurons در روز بین همهٔ این کارها مشترک است؛ Workers Free نیز سقف درخواست روزانه دارد. این سقف‌ها و نبود SLA باید در صف مدیریت شوند.
- Worker یک VPN یا واسطهٔ بی‌طرف برای همهٔ ارائه‌دهندگان نیست؛ فقط یک درگاه server-side است. اگر خود دامنه‌های Cloudflare از مسیر میزبان سایت قابل دسترس نباشند، مسیر دوم لازم است و هیچ دسترسی دائمی تضمین نمی‌شود.

- Laravel فقط به درگاه‌های FARAST وصل شود؛ کلیدهای Gemini/Groq/Cloudflare در محیط درگاه‌ها بمانند، نه در مرورگر و نه در کد سایت.
- درگاه بیرونی برای مدل‌های قوی، همان Worker واحد است؛ هیچ API key مدل در Laravel یا مرورگر قرار نمی‌گیرد.
- Runflare Gateway مسیر دوم برای چت/ویرایشگر است، نه VPN. اگر Worker از خود Runflare هم قابل دسترس نباشد، هیچ relay رایگانِ قابل‌اعتمادِ تأییدشده‌ای وجود ندارد که تضمین کند از هر دو طرف آزاد است؛ در آن وضعیت job در Laravel می‌ماند.
- اگر مسیر مستقیم Laravel به Worker timeout یا فیلتر شد، Laravel مسیر Runflare Gateway را امتحان می‌کند. اگر هر دو شکست خوردند، job در صف می‌ماند و بعداً retry می‌شود.
- پروفایل خصوصی، حافظهٔ کاربر، استنباط رفتاری پنهان، credential و تاریخچهٔ نامرتبط هرگز به مدل ارسال نمی‌شود. متن انتخاب‌شدهٔ کاربر فقط وقتی او صریحاً عملیات AI را اجرا کند و فقط به اندازهٔ لازم ارسال می‌شود؛ فایل محصول نیز از مسیر Worker با سیاست ZDR پردازش می‌شود.
- درگاه‌ها فقط از ارائه‌دهندگانی استفاده کنند که شرایط و منطقهٔ میزبانی درگاه را مجاز می‌دانند. هیچ تضمینی وجود ندارد که یک واسطهٔ رایگان از هر دو سمت همیشه قابل دسترس بماند.

**وضعیت اصلاح‌شده:** در PR #753، درگاه واحد Cloudflare Worker برای متن، بازبینی metadata، تصویر و صوت آماده شده است. Laravel و Product Supervisor فقط به Worker یا gateway داخلی متصل می‌شوند؛ کلید Cloudflare در Worker می‌ماند. fallback مستقیم Gemini در مسیر metadata به‌صورت پیش‌فرض خاموش است.

## 3. محدودیت دوم: قطع کامل اینترنت بین‌الملل

در این حالت، تنها ذخیره‌سازی داخل ایران کافی نیست. برای در دسترس بودن کامل سایت، خود برنامهٔ Laravel، دیتابیس اصلی، session/cache/queue، DNS، احراز هویت، پیامک و هر وابستگی حیاتی نیز باید داخل ایران یا دارای مسیر داخلی آزمایش‌شده باشند.

### فضای ذخیره‌سازی داخل ایران: ArvanCloud Object Storage

طبق صفحهٔ رسمی قیمت‌گذاری فعلی:

- بستهٔ پایه: ۵ گیگابایت فضای ذخیره‌سازی و ۲۰ گیگابایت ترافیک رایگان.
- سقف رایگان درخواست خواندن و نوشتن در جدول قیمت‌گذاری درج شده است؛ مصرف بیش از سقف، رایگان نیست.
- بستهٔ پایه محدودیت زمانی ندارد و هر ۳۰ روز به‌شکل خودکار تمدید می‌شود.
- سرویس رایگان تحت SLA و جبران خسارت اختلال قرار نمی‌گیرد؛ قابلیت‌های پیشرفته‌ای مانند replication در بسته‌های بالاتر قرار دارند.

بنابراین ArvanCloud فعلاً بهترین نامزد بررسی‌شده برای فضای S3-compatible داخل ایران است، اما **۵ گیگابایت را نباید فضای نامحدود یا تضمین پایداری سازمانی دانست**. این سهمیه برای شروع و نگهداری داده‌های حیاتی محدود مناسب است، نه ده‌ها گیگابایت دانش.

منابع رسمی:
- https://www.arvancloud.ir/fa/pricing/cloud-storage
- https://www.arvancloud.ir/fa/pricing/free
- https://docs.arvancloud.ir/en/object-storage/s3

### نحوهٔ استفاده در FARAST

- از همان `StorageManager` و `S3CompatibleAdapter` موجود استفاده می‌شود؛ آداپتر یا جدول ذخیره‌سازی جدید نمی‌سازیم.
- ArvanCloud پس از ساخت حساب و تست واقعی، به‌عنوان volume در `iran_primary` ثبت می‌شود.
- نسخهٔ پشتیبان دیتابیس و فایل‌ها از مسیر موجود `StorageBackupService` به volume مستقل `foreign_backup` (Backblaze B2) به‌صورت AES-256، checksum و restore verification فرستاده می‌شود؛ دو نسخهٔ هفتگی آخر نگه داشته می‌شوند و backup دستی خودکار حذف نمی‌شود. سهمیهٔ بکاپ ظرفیت عملیاتی Arvan را افزایش نمی‌دهد.
- `iran_backup` در کد به‌صورت replica اختیاری وجود دارد، اما اگر در همان حساب Arvan باشد، نسخهٔ مستقل از خرابی ارائه‌دهنده محسوب نمی‌شود و از ظرفیت همان حساب استفاده می‌کند؛ فعلاً آن را فعال نمی‌کنیم.
- فایل‌های محصول، تصاویر محصول، منابع دوره و فایل‌های خصوصی ویرایشگر باید با طبقه‌بندی `critical` به `iran_primary` بروند؛ در PR #753 آپلود فایل خصوصی ویرایشگر نیز از `non_critical` به `critical` تغییر می‌کند تا به `foreign_primary` نرود.
- داده‌های دانش، chunkها، مجوزها و حافظهٔ خصوصی کاربر همچنان در MySQL فعلی باقی می‌مانند؛ Object Storage جایگزین دیتابیس رابطه‌ای نیست.

### هاست داخلی: Runflare

پلن رایگان فعلی Runflare شامل ۳ گیگابایت RAM، حدود ۱٫۵ هسته CPU، ۳ گیگابایت دیسک و حداکثر دو Deployment در کلاستر تهران است. اما خود Runflare صریحاً می‌گوید پلن رایگان برای توسعه و تست است، بکاپ ندارد، Production را تضمین نمی‌کند و پس از سه ماه سرویس و داده‌ها حذف می‌شوند.

دو Deployment رایگان Runflare برای دو نقش موجود استفاده می‌شوند:
1. **Product Supervisor:** استخراج ساختاری و ساخت chunk داخل ایران؛ inference مدل از طریق Worker بیرونی. در قطعی بین‌الملل، متن قابل استخراج را ذخیره می‌کند و وضعیت AI را pending نگه می‌دارد.
2. **Voice-typing Gateway:** bridge stateless برای چت/ویرایشگر، به‌عنوان مسیر دوم به Worker.

هیچ فایل، دیتابیس، دانش، token یا دادهٔ دائمی روی Runflare ذخیره نمی‌شود. مدل بزرگ ۲۰B/۱۲۰B روی منابع آن اجرا نمی‌شود. مدل Qwen3 1.7B موجود در مخزن مکمل legacy است و اسکریپت استقرار جدید آن را فعال نمی‌کند. در قطعی کامل بین‌الملل، AI تولیدی متوقف می‌شود؛ اما استخراج محلی، فایل اصلی و jobهای پایدار در ایران حفظ می‌شوند و پس از برگشت اتصال retry می‌شوند.
- شرایط Runflare اجرای VPN، پراکسی و تونل را ممنوع می‌کند؛ از این سرویس برای عبور ترافیک استفاده نمی‌کنیم.

### تمدید سه‌ماهه و بازیابی

در مخزن مکمل، اسکریپت استقرار Runflare از قبل وجود دارد؛ آن را جایگزین یا موازی نمی‌کنیم. CLI رسمی فرمان deploy دارد، اما پس از حذف کامل پروژه، انتخاب/ساخت پروژه و سرویس جدید همچنان به حساب مالک نیاز دارد. بنابراین «یک کلیک کاملاً خودکار پس از حذف» هنوز اثبات نشده است.

هدف اجرایی این است که پس از ساخت مجدد سرویس در پنل، یک فایل CMD واحد:
1. CLI را در صورت نیاز نصب کند؛
2. از حساب موجود login کند؛
3. سورس همان شاخهٔ Git را deploy کند؛
4. تا پاسخ سالم health check صبر کند؛
5. فقط پس از تأیید، نشانی جدید را برای ثبت در تنظیمات سایت نمایش دهد.

اسکریپت‌های جداگانهٔ `deploy-runflare.cmd` برای Product Supervisor و Voice-typing Gateway آماده شده‌اند. بعد از تست اولین استقرار، آن‌ها را در یک launcher واحد ادغام می‌کنیم؛ CLI نمی‌تواند پروژه/سرویس حذف‌شده را خودکار در پنل ایجاد کند.

## 4. APIهای رایگان جایگزین و مرز حریم خصوصی

- **Cloudflare Workers AI:** انتخاب اول فعلی؛ ۱۰٬۰۰۰ Neurons در روز رایگان. باید مصرف هر درخواست و سهمیهٔ روزانه کنترل شود. منبع: https://developers.cloudflare.com/workers-ai/platform/pricing/
- **Kilo Gateway و OVHcloud AI Endpoints:** بررسی شدند اما انتخاب Production نیستند؛ محدودیت سهمیه، مسیر ناشناس/ارائه‌دهندهٔ ثالث و شفافیت کمتر در کنترل محل پردازش، آن‌ها را برای فایل‌های محصول و حافظهٔ خصوصی مناسب نمی‌کند. در صورت نیاز فقط برای دادهٔ عمومی و پس از بازبینی جداگانه قابل ارزیابی‌اند.
- **SambaNova:** پلن فعلی برای شروع درخواست‌ها افزودن روش پرداخت می‌خواهد؛ با شرط بدون کارت/پرداخت خارجی انتخاب نمی‌شود. منبع: https://cloud.sambanova.ai/plans
- **Groq و Gemini:** به‌دلیل شواهد محدودیت منطقه‌ای/شرایط نگهداری داده، برای مسیر حیاتی یا دادهٔ خصوصی انتخاب پیش‌فرض نیستند.

## 5. تصمیم نهایی معماری

| لایه | انتخاب | نقش و محدودیت |
|---|---|---|
| هسته و منبع حقیقت | Laravel + MySQL فعلی | کاربران، محصولات، مجوزها، knowledge chunks، حافظه خصوصی و صف |
| فایل‌های حساس داخل ایران | ArvanCloud S3-compatible | سهمیه رایگان ۵GB؛ از مسیر StorageManager |
| بکاپ | StorageBackupService موجود | AES-256، checksum و restore؛ مقصد ایرانی با سهمیهٔ واقعی |
| AI قوی بیرونی | Cloudflare Workers AI از یک Worker واحد | GPT-OSS 20B برای متن، GPT-OSS 120B برای reviewer، Moondream برای تصویر، Whisper برای صوت؛ سهمیه روزانه مشترک |
| پردازش داخلی | Runflare Product Supervisor | استخراج محلی فایل و نگهداری موقت؛ بدون ذخیرهٔ دائمی یا مدل محلی |
| gateway داخلی | Runflare Voice-typing Gateway | bridge stateless به Worker برای failover چت؛ بدون DB، فایل دائمی، VPN یا مدل محلی |
| پردازش batch | Google Colab موجود | موقت و غیرهمیشگی؛ checkpoint و خروجی باید به storage پایدار برگردند |
| جست‌وجوی برداری | فعلاً اضافه نشود | chunkها در MySQL موجودند؛ Qdrant فقط پس از آزمون retrieval و نیاز واقعی اضافه می‌شود |

### مواردی که فعلاً انتخاب نمی‌شوند

- VPN رایگان عمومی یا پراکسی ناشناس: غیرقابل اتکا و دارای ریسک حریم خصوصی.
- Qdrant Cloud Free به‌عنوان منبع اصلی دانش: ظرفیت و پایداری کافی ندارد و با وجود chunkهای فعلی MySQL فعلاً ضروری نیست.
- Runflare به‌عنوان دیتابیس یا فضای دائمی: حذف سه‌ماهه و نبود backup آن با دادهٔ حیاتی سازگار نیست.
- اجرای GPT-OSS 20B روی Runflare: از نظر RAM/CPU/disk این پلن ممکن نیست.
- ذخیرهٔ پروفایل رفتاری کاربران در vector index یا سرویس عمومی: ممنوع.

## 6. محدودیت ظرفیت رایگان

تا این ممیزی، گزینهٔ ایرانی با ظرفیت ده‌ها گیگابایت، رایگان، دائمی، دارای SLA و backup مستقل پیدا نشده است. نامزد رسمی و قابل‌استناد فعلی ArvanCloud فقط ۵ گیگابایت فضای رایگان، ۲۰ گیگابایت ترافیک و سقف ۱۰٬۰۰۰ درخواست دارد و برای این بسته SLA تولیدی اعلام نشده است. بنابراین تا زمان رشد ظرفیت، فایل‌های حیاتی و خصوصی در `iran_primary` و MySQL ایران می‌مانند؛ backup رمزگذاری‌شده در `foreign_backup` نگهداری می‌شود؛ فایل‌های حجیم غیرحیاتی می‌توانند از `foreign_primary` استفاده کنند؛ و هیچ داده‌ای فقط روی Runflare باقی نمی‌ماند.

**وضعیت کد:** PR #753 در مخزن `non` درگاه Cloudflare Worker و حذف fallback مستقیم provider از Laravel را آماده کرده است؛ PR #16 در مخزن `Voice-typing` Runflare را به bridge همان Worker تبدیل می‌کند. هر دو تا زمان استقرار واقعی و تست URLها باز می‌مانند و نباید زودتر merge شوند.

**پیش‌شرط قطعی برای تضمین حالت قطع بین‌الملل:** محل فیزیکی هاست اصلی Laravel و MySQL باید مشخص و داخل ایران باشد. این اطلاعات از فایل‌های مخزن قابل اثبات نیست؛ تا زمان تأیید آن، فقط می‌توان گفت ذخیره‌سازی و صف برای بازیابی آماده می‌شوند، نه اینکه کل سایت در زمان قطعی بین‌الملل حتماً آنلاین می‌ماند.

**ترتیب اولویت:** عدم از دست رفتن داده > حفظ حریم خصوصی > failover بدون اتصال مستقیم سایت به provider > بازیابی داخلی > افزایش ظرفیت و کیفیت مدل.


## اصلاحات معماری و محدودیت‌ها — ۲۷ نوامبر ۲۰۲۶

این بخش، موارد قدیمی‌تر همین سند را در صورت تعارض اصلاح می‌کند:

1. **Runflare فقط پردازشگر محلی موقت است.** پلن رایگان ۳ ماهه، بدون backup و بدون تضمین Production است. بعد از حذف، باید پروژه و سرویس جدید در پنل ساخته شود و سپس اسکریپت deploy اجرا شود؛ CLI فعلی ساخت خودکار پروژهٔ حذف‌شده را مستند نکرده است. از Runflare برای عبور درخواست به‌عنوان پراکسی/تونل استفاده نمی‌کنیم؛ شرایط استفادهٔ آن این دسته را ممنوع می‌کند. PR #16 در مخزن Voice-typing همچنان Draft است و تا تأیید کتبی Runflare نباید Deploy شود.

2. **مسیر ارتباطی دوم چت، Netlify Functions است، نه Runflare.** PR #759 یک Function محدود و احراز هویت‌شده اضافه کرده که فقط endpointهای ثابت FARAST را به همان Cloudflare Worker می‌فرستد. این سرویس مدل یا سهمیهٔ جدید ایجاد نمی‌کند؛ فقط وقتی اتصال شبکه‌ای هاست Laravel به Worker برقرار نمی‌شود و Netlify می‌تواند وصل شود مفید است. پاسخ‌های 401/403/429 و خطای خود Worker با آن حل نمی‌شوند. این PR هنوز باید CI کامل و تست زنده از هاست واقعی را بگذراند.

3. **Cloudflare AI Search از قبل در main وجود دارد، اما اتصال Laravel به آن هنوز انجام نشده است.** فقط برای نمایهٔ قابل‌بازسازیِ metadata تأییدشدهٔ محصولات و دادهٔ عمومی استفاده خواهد شد. سهمیهٔ رایگان اعلام‌شده شامل ۱۰GB فضای index، ۵ میلیون توکن ingestion، ۱٬۰۰۰ جست‌وجوی semantic و ۱٬۰۰۰ جست‌وجوی full-text در ماه است. هیچ حافظهٔ خصوصی، شناسهٔ حساب یا پروفایل رفتاری به آن فرستاده نمی‌شود. Qdrant فعلاً اضافه نمی‌شود تا موتور موازی نسازیم.

4. **Arvan Object Storage بهترین گزینهٔ رایگان ایرانیِ تأییدشده است، اما ظرفیت آن کوچک است:** ۵GB فضا، ۲۰GB ترافیک و ۱۰٬۰۰۰ درخواست read/write در بستهٔ رایگان؛ بدون SLA، replication یا query engine. سهمیهٔ bucketهای یک حساب مشترک است. نسخهٔ کامل رمزگذاری‌شدهٔ MySQL را می‌توان با مقصد موجود iran_backup در همان Arvan نگه داشت، اما فقط پس از بررسی اینکه فایل‌های اصلی به‌علاوهٔ یک backup در ۵GB جا می‌شوند. Backblaze B2 همچنان کپی مستقل خارجی است.

5. **محدودیت قطع اینترنت بین‌الملل:** Runflare می‌تواند استخراج و صف محلی را انجام دهد، اما بدون دسترسی به مدل خارجی تحلیل قوی تولید نمی‌کند. jobها و فایل‌ها حفظ و پس از بازگشت اینترنت retry می‌شوند؛ ادعای پردازش AI قوی در زمان قطعی نداریم.

6. **وضعیت PRها:** PR #753 هنوز Draft و نیازمند به‌روزرسانی نسبت به main و اجرای کامل CI است؛ PR #758 ادغام شده و اصلاح وضعیت‌سنجی provider و جداول voice را وارد main کرده؛ PR #759 مسیر دوم Netlify را اضافه می‌کند و تا پایان CI/تست واقعی فعال نمی‌شود.
